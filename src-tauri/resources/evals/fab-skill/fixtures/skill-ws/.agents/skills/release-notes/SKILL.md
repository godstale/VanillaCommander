# Release Notes

Read the provided change list, then write RELEASE-NOTES.md with exactly these sections:

## Highlights

User-facing improvements, one bullet per change.

## Breaking Changes

Incompatible changes with migration notes. Write "None." when there are none.

## Contributors

Names or handles of contributors, one per line.

Rules:

- Never invent changes that are not in the source material.
- Keep bullets under 20 words.
