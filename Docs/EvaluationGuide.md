# Fortress 자동 평가 사용법 (Evaluation Guide)

> **폐기됨 (Vanilla Commander 전환, P11-03)**: 평가 기능은 앱에서 제거되었습니다. 외부 LLM API/에이전트 CLI 등록은 에이전트 편집으로 이관 예정(P11-22)이며, 전송 감사 로그는 설정에 남습니다. 이 문서는 이력으로만 보존합니다.

평가셋(팩)을 이용해 여러 후보(모델×설정)를 같은 조건으로 자동 실행하고,
품질·에이전트·성능·자원·신뢰성을 0~100 공통 척도로 비교해
이 PC와 작업에 가장 맞는 후보를 추천받는 기능의 사용 설명서입니다.

> 요약본은 `UserGuide.md` §8에도 있습니다. 이 문서는 전체 절차·옵션·결과 읽기를 다룹니다.

---

## 1. 개념 잡기

| 용어 | 의미 |
| :--- | :--- |
| **평가셋(팩)** | 문제+정답+채점 규칙 묶음. 내장 20종 + 직접 만든 개인 팩 |
| **후보** | 비교 대상인 "에이전트(모델×설정)" 1개. 실행은 후보 여러 개를 같은 팩으로 돌림 |
| **프로파일** | "무엇을 중시할지" 기준 조합(차원 가중치 + 컷라인 제약). 내장 5종 |
| **Judge** | 작문·루브릭 계열처럼 정답 대조가 어려운 팩을 채점하는 LLM(로컬 또는 외부) |
| **Arena** | 두 후보를 블라인드로 비교 투표해 선호 순위를 매기는 별도 모드 |
| **EEE 내보내기** | 실행 결과를 외부 교환 포맷(JSON)으로 저장하는 기능 |

### 1.1 평가셋(팩) 3계층

| 계층 | 위치·의미 | 편집 |
| :--- | :--- | :--- |
| **내장(builtin)** | 앱 번들 20종, 읽기 전용 | [복제해서 편집]으로 개인 사본 생성 |
| **전역(user)** | 이 PC의 내 팩(`app_data/evals/packs/<id>/`) | 편집·삭제 가능 |
| **프로젝트(project)** | 워크스페이스별 팩(`{ws}/.fortress/evals/packs/<id>/`) | 편집·삭제 가능, 전역으로 승격(복사) 가능 |

### 1.2 내장 팩 20종

- **FAB 11종**(Fortress 자체 제작): `fab-tools-select`, `fab-tools-relevance`, `fab-viz`,
  `fab-fs-tasks`(파일 작업, 픽스처 포함), `fab-skill`, `fab-compaction`,
  `fab-longctx`, `fab-perf-probe`, `fab-ko-writing`, `fab-code-js`, `fab-quant-probe`
- **공개셋 9종**(원본 라이선스·출처 표기, 변환 스크립트 버전까지 기록):
  `gsm8k`, `gsm8k-perturb`, `mmlu-pro`, `ifeval`, `ko-ifeval`,
  `kmmlu`(원본 CSV 무수정 번들), `kobest`, `humaneval-plus`(Python 필요), `bfcl`
- 라이선스 문제로 번들하지 않는 셋(HAE-RAE, GPQA, CLIcK, LogicKor 등)은
  **가져오기 프리셋**으로만 제공됩니다. GPQA는 평문 공개 금지 요청에 따라
  내보내기 시 샘플 원문이 제외됩니다.

### 1.3 분량 조절 (크기 선택 + 팩별 세부)

마법사 평가셋 단계의 **크기 선택**으로 분량을 자동조합합니다.
처음에는 **Quick(약 30분)** 으로 흐름을 익히고,
본 비교는 **Standard(약 1시간 반)** 이상을 권장합니다.

| 크기 | 동작 |
| :--- | :--- |
| **Quick** | 가중치가 0이 아닌 카테고리마다 대표 팩을 최대 6개까지 smoke 분량으로 조합 (`long_context`·`agentic`·`logprob_trace` 계열 제외) |
| **Standard** | 가중치가 0이 아닌 카테고리의 팩 전체를 표준 분량으로 조합 |
| **Full** | 전체 팩·전체 분량 (수 시간 소요 가능) |

팩별 tier(Smoke/Standard/Full)·epochs(반복 횟수)·circular(순환)은
**고급(팩별 세부)** 폴드에서 직접 바꿀 수 있습니다.
표본이 작으면 리포트의 "구분 불가"가 늘어나고 검정력 경고가 표시됩니다.

## 2. 평가 실행 만들기 (마법사 4단계)

평가 패널(좌측 ActivityBar의 평가 항목, 아이콘 `FlaskConical`) 또는
상단 메뉴 "평가" → **[새 평가]**를 누르면 실행 마법사가 열립니다.

### 2.1 단계 1 — 목적(프로파일)

내장 5종 + 저장한 사용자 프로파일이 카드로 표시됩니다.
카드에는 차원 가중치 막대와 제약 요약이 보입니다.

- **[복제해서 편집]** → 차원·카테고리 가중치 슬라이더, 제약 추가/삭제,
  성능 앵커 덮어쓰기 → `saveProfile`로 저장.
- 프로파일을 바꾸면 뒤쪽 확인 단계의 체크가 초기화되므로 마지막에 다시 확인합니다.

### 2.2 단계 2 — 평가셋 선택

- 팩 목록이 카테고리별 그룹 + 계층 배지(builtin/user/project) + 라이선스 +
  진단 오류 표시와 함께 나옵니다.
- **크기 선택(Quick / Standard / Full)** 으로 팩 조합과 분량을 자동조합합니다(§1.3).
  팩별 tier(Smoke/Standard/Full)·epochs(반복 횟수)·circular(순환)는 **고급(팩별 세부)** 폴드에서 바꿉니다.
- 현재 프로파일에서 가중치가 0인 카테고리의 팩은 흐리게 표시됩니다.

### 2.3 단계 3 — 후보·평가 모델·실행 옵션

- **에이전트 선택** 탭: 에이전트 다중 선택(Provider·모델·컨텍스트 표시,
  외부 후보는 배지 + 권한 상태 표시).
- **매트릭스** 탭: 기준 에이전트 + 축 입력(모델은 드롭다운 다중 선택,
  수치 축은 콤마 입력)으로 조합을 자동 생성. **24개 초과 시 오류**가 나므로
  축을 나눠 여러 번 실행하세요.
- **양자화 비교(Q8)** 토글: 기준 후보를 고르면 양자화 충실도 표가 리포트에 추가됩니다.
- **평가 모델 설정** (모델 채점이 필요한 팩을 고른 경우만 표시): 로컬 모델 또는
  권한 있는 외부 연동의 `judge` 용도만 목록에 나옵니다. 척도와 쌍대(순서 교체) 모드 지정.
- **실행 옵션**: 결정성 모드, reliability epochs, 타임아웃 배수, perf 반복 측정,
  후보 간 모델 언로드 여부.

### 2.4 단계 4 — 검토 후 실행 생성 (여기서만 [실행 생성] 가능)

1. **사전점검 결과표**(후보×항목, 차단/경고)를 확인합니다.
   도구 미지원·logprobs·코드 런타임 불충족 항목은 여기서 최종 갱신됩니다.
2. **예상 시간**(후보별·합계)과 **검정력 안내**
   ("팩 X: 구분 가능한 최소 차이 ≈ ±N%p")를 보고 분량이 충분한지 판단합니다.
3. **가중치·기준값 확인 패널**: 이번 실행에 쓸 차원·카테고리 가중치와
   성능 앵커(예: "decode 3 tok/s = 0점, 60 tok/s = 100점, 로그 곡선")를 표로 모두 보고,
   이 자리에서 수정할 수 있습니다. 수정분은 이번 실행의 프로파일 사본에만 반영되며
   [프로파일로 저장]도 선택할 수 있습니다.
4. 하단 체크박스 **"가중치를 확인했습니다"**를 체크해야 버튼이 활성화됩니다.
5. 외부 요소가 있으면 **외부 전송 요약**(연동별 용도·데이터 분류·예상 요청 수·토큰)과
   "외부 전송에 동의합니다" 체크가 추가됩니다. 동의하지 않으면 외부 요소를
   제외하고 진행할지 묻습니다.
6. Python 코드 실행이 있으면 코드 실행 확인 체크가 추가됩니다.
7. **[실행 생성]** → "평가가 등록되었습니다" 팝업 →
   **[즉시 실행] / [나중에 실행]** 선택. [즉시 실행]만 바로 실행되며,
   [나중에 실행]은 목록에 `pending`으로 남아 패널의 [시작]을 눌러야 실행됩니다.
   **자동 시작·예약 실행은 없습니다.**
8. 다른 평가가 실행 중(잠금 중)에는 마법사를 열 수 있어도 [즉시 실행]은 비활성화됩니다.

## 3. 평가 중 알아둘 것 (잠금)

평가가 시작되면 **전역 평가 잠금**이 걸립니다.

- 모든 채팅의 입력·전송·큐 등록·슬래시 명령이 차단되고, 입력창 플레이스홀더가 바뀝니다.
- 폴더 전환과 에이전트 편집도 함께 잠깁니다(기존 전역 busy 경로 재사용).
- 새 채팅 탭을 여는 것은 가능하지만(열람용) 전송은 되지 않으며,
  평가가 끝나도 입력했던 내용이 **자동 전송되거나 큐에 남지 않습니다**.
- 채팅 탭 상단에 잠금 배너("평가 실행 중: {실행 이름} …")와 **[진행 상황 보기]** 버튼이 표시됩니다.
- 진행 중 채팅이나 대기 큐가 있으면 평가를 시작할 수 없습니다. 먼저 채팅을 끝내세요.
- 중간에 앱을 종료하면 해당 실행은 **`interrupted`**로 표시되고,
  목록의 **[이어하기]**(확인 팝업 후 시작)로 남은 Trial부터 계속할 수 있습니다.

## 4. 진행 화면 읽기

실행이 시작되면 같은 탭(`eval:run:{runId}`)이 진행 화면으로 바뀝니다.

- **헤더**: 실행 이름, 상태 배지, 전체 진행률, 경과·남은 시간,
  [일시정지]/[재개]/[후보 건너뛰기]/[취소](확인 팝업).
- **후보×팩 매트릭스**: 셀마다 진행률과 현재까지의 정답률(대표 지표), 실행 중 셀 강조.
- **현재 샘플 미리보기**: 입력 앞부분 + 스트리밍 출력 + 도구 호출 목록(agentic).
- **자원 미니 차트**: 최근 120초 decode tok/s·VRAM·GPU 사용률.
- **로그**: 경고·skip 사유·오류(최근 200줄).
- 상태가 `completed`가 되면 같은 탭이 자동으로 리포트 뷰로 전환됩니다.

## 5. 리포트 읽기

### 5.1 추천과 순위

- **추천 카드 3종**: 최적 / 빠른 대안 / 고품질 대안 + 사유 문장.
  매트릭스 후보라면 [이 설정으로 에이전트 만들기]로 바로 에이전트를 생성할 수 있습니다.
- **순위표**: 종합 점수(±신뢰구간), 차원 점수 5개, 커버리지 %,
  제약 위반 배지(툴팁에 내용). "구분 불가" 그룹은 같은 순위 번호 + 음영 처리.
  원시값 보기 토글로 정규화 전 값도 확인 가능합니다.

### 5.2 차트

- 차원 레이더(후보 최대 6개 선택), 파레토 산점도(x=성능, y=품질+에이전트 평균,
  버블=VRAM 피크, 파레토 선), 카테고리 히트맵,
  컨텍스트 길이별 정확도·decode 곡선(Q6·P2 데이터가 있을 때).

### 5.3 드릴다운과 사람 채점

- 팩 → 샘플 목록(후보별 ✓/✗/△/—) → 샘플 상세:
  입력, 후보별 출력 나란히 보기, 사고 내용 접기, 도구 궤적,
  최종 파일 상태 diff(픽스처 대비), 채점기별 점수·사유, Judge 원문.
- 샘플 상세에서 직접 점수를 매기면(**사람 채점**) 집계가 다시 계산되어 화면이 갱신됩니다.

### 5.4 경고 영역과 실행 비교

- 경고 영역에서 Judge 신뢰 낮음, 길이 편향, 자기 계열 Judge, 결정성 모드,
  샘플 수 부족(검정력) 등을 확인하세요.
- **실행 비교**: 같은 팩 해시를 가진 이전 실행과 후보별 점수 변화 비교(회귀 ↓ 강조).
  하드웨어 지문이 다르면 성능·자원 비교는 차단되고 사유가 표시됩니다.
- 리포트의 **내보내기** 버튼으로 EEE JSON·CSV를 저장합니다(§8).

## 6. 개인 평가셋 (내 대화를 평가 케이스로)

### 6.1 채팅에서 1건 저장

사용자 말풍선의 [⋯] → **"평가 케이스로 저장"** (`PersonalCaseDialog`):

1. **입력**: 해당 사용자 메시지 + 직전 대화 N개(기본 4, 조정 가능)가 변환됩니다
   (도구 결과 메시지는 요약 문자열로 치환).
2. **기준**(복수 선택): 참조 답변(현재 어시스턴트 응답 또는 직접 편집),
   결정적 체크(포함 키워드·JSON·Mermaid/Recharts 블록·정규식), 루브릭.
3. **픽스처 캡처**(도구를 쓴 대화일 때 선택): 대화에서 read/write/edit한 파일 경로를
   체크리스트로 보여주고, 고른 파일 내용을 픽스처로 복사합니다
   (파일당 256KB, 합계 1MB 상한).
4. **비밀값 보호**: `.env*`, `*.pem`, `*.key`, `id_rsa*`, `credentials*` 경로와
   키·토큰·비밀번호 패턴 값은 자동 제외·마스킹되며 미리보기에서 강조됩니다.
5. **저장 대상**: 프로젝트 개인 팩(기본 `personal-<프로젝트폴더명>`, 없으면 자동 생성,
   카테고리 Q9) 또는 전역 개인 팩.

### 6.2 일괄 초안과 팩 편집

- **일괄 초안**(`BulkDraftDialog`): 최근 세션을 다중 선택 → 세션마다 마지막 요청·응답으로
  초안 케이스 생성 → 표에서 검토·수정·체크한 것만 저장. 자동 저장은 없습니다.
  권한이 있으면 "외부 모델로 참조 답변/루브릭 초안 만들기"도 가능하며,
  실행 전 전송 요약 확인을 받습니다.
- **팩 편집기**: 매니페스트 폼(카테고리·kind·채점기·지표·tier·systemPrompt) +
  샘플 표(추가·삭제·복제·순서) + kind별 샘플 편집기.
  저장 시 zod 검증, 버전 patch 자동 증가.
- 팩 관리 화면의 **[전체 검증]**으로 모든 팩의 진단을 한 번에 확인할 수 있습니다.

---

## 7. Arena (블라인드 선호 투표)

1. 채팅 탭 헤더의 **[비교 모드]** 버튼 → Arena 뷰(또는 `eval:arena` 탭).
   에이전트 2개를 고릅니다(같은 에이전트 불가).
2. 입력하면 두 후보에 **순차 전송**됩니다(VRAM 경합 방지, 순서 무작위).
   단일 턴·도구 없음, 응답은 좌/우 무작위 배치, 모델명은 숨겨집니다.
3. **투표**: A가 낫다 / B가 낫다 / 무승부 / 둘 다 나쁨 → 투표 후 모델명 공개.
4. **리더보드**: 전체 투표로 Bradley-Terry 점수 + 95% CI, 후보별 투표 수.
   **30표 미만이면 "표본 부족"** 표시. 투표 목록 확인·삭제 가능.
5. 투표한 입력은 [평가 케이스로 저장]으로 개인 팩에 넣을 수 있습니다.
6. 평가 잠금 중에는 Arena 전송도 불가합니다.

## 8. 가져오기·내보내기

### 8.1 가져오기 (외부 평가셋을 내 팩으로)

- **파일 선택** 또는 **HF 프리셋 다운로드**(사용자 클릭 시에만.
  다운로드 전 URL·크기·라이선스를 표시) → 형식 감지(JSONL/JSON 배열/CSV) →
  **필드 매핑**(input/target/choices/id/metadata 열 선택.
  Inspect·OpenAI Evals·promptfoo 프리셋은 자동 매핑) →
  채점기·카테고리·kind 선택 → **미리보기 5행** → user 또는 project 팩으로 저장.
- **promptfoo 변환 대응**: `equals→exact`, `contains/icontains→includes`,
  `regex→regex`, `is-json→json_schema`, `llm-rubric→llm_judge_rubric`,
  `javascript/python` 등은 미지원 목록으로 보고됩니다.
- 다운로드한 원본은 user 계층 팩 폴더에 저장됩니다.

### 8.2 내보내기 (리포트의 내보내기 버튼)

- **EEE JSON**: 실행 1건 → 후보별 aggregate JSON + 샘플 JSONL.
  하드웨어 지문 등 EEE에 없는 필드는 확장 필드 또는 `source_metadata` 설명에 요약.
- **CSV**: 순위표·샘플 결과.
- 개인 팩 포함 여부 확인(기본 제외, 포함 시 경고).

## 9. 외부 연동 (옵트인)

외부 LLM API·에이전트 CLI를 Judge·후보 등으로 쓰려면 **설정 > 외부 연동**에서
마스터 스위치를 켜야 합니다. 끄면 마법사에서 외부 옵션이 숨겨집니다.
용도·데이터 분류별 동의를 받고, 실행마다 다시 확인하며,
모든 외부 전송은 감사 로그에 기록됩니다.
개인 팩은 내보내기·외부 전송에서 `personal` 데이터 분류로 취급되므로
외부 Judge·외부 참조 초안에 쓸 때 전송 요약 확인이 뜹니다.

## 10. 문제 해결

| 증상 | 확인 사항 |
| :--- | :--- |
| [실행 생성]이 비활성 | "가중치를 확인했습니다" 체크 여부. 모델 채점 필요 팩인데 평가 모델 미설정, 외부 요소 미동의, Python 확인 미체크도 원인 |
| [즉시 실행]이 비활성 | 다른 평가 실행 중(잠금 중). 마법사는 열 수 있지만 시작은 대기해야 함 |
| 평가를 시작할 수 없음 | 진행 중 채팅·대기 큐가 있으면 잠금 획득 실패. 채팅을 먼저 끝내세요 |
| 실행이 `interrupted` | 앱 종료 등으로 중단됨. 목록에서 [이어하기]로 남은 Trial부터 계속 |
| HumanEval+ 계열이 skip | Python 실행 환경이 없는 PC에서는 코드 실행 팩이 skip됩니다. JS 코드 팩(`fab-code-js`)으로 대조 실행 |
| 추천이 "구분 불가"로만 나옴 | 신뢰구간 겹침. 에폭 증가·상위 tier(더 많은 샘플)로 다시 실행 |
| 비교에서 성능·자원 칸이 막힘 | 이전 실행과 하드웨어 지문이 다르면 차단됨. 같은 PC·같은 조건에서 재실행 |
| EEE 파일 검증 실패 | EEE 스키마 버전이 바뀐 경우. 구현 시점 최신 버전에 맞춰 저장되므로 스키마 버전을 확인하세요 |
